# Stage 0: Code vs. Manuscript Discrepancies & Ground Truth Audit (`issues.md`)

## 1. Ground Truth & Benchmark Integrity Issues on the 50 Test Queries (`REAL_Q_01`–`REAL_Q_50`)

1. **ISSUE-GT-01: Missing Human-Verified Page-Level Ground Truth (`gt_pages`) for the 50 Test Queries.**
   - **Observation:** The 50 test queries (`outputs/empirical_50_real_questions_benchmark.json`) have exact, unambiguous **document-level** ground truth (`gt_doc_ids`: 1 paper for `REAL_Q_01..20`, 2 papers for `REAL_Q_21..35`, 3 papers for `REAL_Q_36..45`, 0 papers for `REAL_Q_46..50`), because the exact paper titles are quoted verbatim inside each query. However, no ground-truth page list `(doc_id, page_number)` was ever annotated.
   - **Original Benchmark Behavior:** `run_50_real_questions_benchmark.py::verify_grounding_and_citations` (L93–115) evaluated `[filename - Trang X]` only against the set of `(filename, page_number)` present in the **retrieved `chunks` passed to the LLM** (`Citation-in-Context`), NOT against an external ground-truth page annotation.
2. **ISSUE-GT-02: Oracle Document Filtering (`WHERE c.document_id IN target_ids`) in Original Benchmark.**
   - **Observation:** In `run_50_real_questions_benchmark.py` (L261, L274), both Dense and BM25 SQL queries restricted retrieval to `WHERE c.document_id IN %s` using the oracle `target_ids` of each question (`LIMIT 6`), instead of retrieving across the entire 499-document corpus (`70,825` chunks).
3. **ISSUE-GT-03: Oracle `is_ooc` Context Wiping for Acamind on Refusal Queries.**
   - **Observation:** In `run_50_real_questions_benchmark.py` (L303), for the 5 Safe Refusal queries (`is_ooc=True`), the script passed `[]` (empty context) to `call_gemini_safe` for Acamind (`acamind_chunks if not is_ooc else []`), while passing `dense_rows[:2]` and `bm25_rows[:2]` to Naive Dense and BM25 (L307–308).
4. **ISSUE-GT-04: Query Template vs. Corpus Domain Mismatch on Some arXiv Papers.**
   - **Observation:** Although the 499 arXiv PDFs were queried around cognitive/clinical/AI topics, several papers among the first 60 (`REAL_Q_01` `'AlignQuant: Tile-Aligned Mixed-Precision Quantization...'`, `REAL_Q_02` `'What Matters for Latent Reasoning with Flow Matching'`, etc.) are general ML/LLM papers rather than clinical psychology trials. Because `PSYCHOLOGY_SYSTEM_PROMPT` instructed the LLM to act strictly as a psychology assistant, the LLM refused (`__NO_CONTEXT__`) on several in-corpus ML papers in `empirical_50_real_questions_benchmark.json` (e.g., `REAL_Q_01`). Per Principle 3 (*"KHÔNG sửa ground truth của 50 query test"*), we keep all 50 test queries completely unchanged.

- **`ISSUE-GT-05` (Mixed Vietnamese-English `plainto_tsquery` Boolean-AND Collapse):**
  - In `run_50_real_questions_benchmark.py` (L270–277), Sparse search executes `plainto_tsquery('english', q_text)` without a `WHERE ... @@ plainto_tsquery(...)` predicate. Because `REAL_Q_01`–`REAL_Q_45` wrap English paper titles inside a Vietnamese question template (`"Mục tiêu nghiên cứu, giả thuyết khoa học... trong bài báo '<English title>' là gì?"`), `plainto_tsquery` joins ALL tokens with boolean AND (`&`), requiring every matching chunk to contain the Vietnamese words (`mục`, `tiêu`, `nghiên`, `cứu`, etc.) AND the English words simultaneously.
  - Consequently, `to_tsvector('english', c.content) @@ plainto_tsquery('english', q_text)` evaluates to `FALSE` (`ts_rank_cd = 0.0`) for **50/50** queries! In `run_50_real_questions_benchmark.py`, omitting the `@@` filter in `WHERE` caused PostgreSQL to return 6 arbitrary chunks with `score = 0.0` from `WHERE c.document_id IN target_ids`.
  - Likewise, in `retriever.py` (L416–432, `_bm25_via_fts`), `orig_clause = " & ".join(fts_terms[:4])` takes only the first 4 tokens of the query (which for `REAL_Q_01`–`REAL_Q_45` are always the 4 Vietnamese template words) and joins them with `&`, yielding `0` page hits against the English corpus.
